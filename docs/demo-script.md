# Two-minute NEAR PHOENIX demo and recording plan

## Before recording

1. Use a trusted Ubuntu development machine with Rust, `cargo-near`, Node/npm,
   dependencies, and the local NEAR Sandbox runtime installed. Do not use a
   funded wallet or public network.
2. Run `npm run demo:local` once and retain the printed `/tmp` JSON path. For
   the recording, run the dashboard demo separately so the UI timeline is
   visible; the one-command terminal demo does not launch a browser.
3. In two terminals, start `NEAR_NETWORK=localnet npm run dev:api` and
   `npm run dev:dashboard`. Open `http://localhost:3000`. If RPC telemetry has
   no local contract configuration, leave it visibly unavailable; do not
   imply that it is part of the harness evidence.
4. Start an unedited screen recording. Show the dashboard and then the backend
   terminal or exported JSON. Stop if the demo fails; show the actual failure.

## Narration and actions

### 0:00–0:20 — Explain the boundary

**Show:** Dashboard and its Sandbox/local-demo context.

**Say:** “NEAR PHOENIX is a local recovery prototype for paid autonomous-agent
tasks. This run uses disposable NEAR Sandbox accounts only. The dashboard
displays events emitted by the local integration harness; it is not a public
network deployment.”

### 0:20–0:45 — Start and checkpoint work

**Show:** Start the local demonstration. Point out `primary_heartbeat` and
`checkpoint_committed`.

**Say:** “The deterministic primary worker signs a heartbeat and a
task-bound checkpoint. STATEFLOW validates the signed checkpoint lineage before
the recovery path can use it.”

### 0:45–1:10 — Fail over safely

**Show:** `primary_failed`, then `backup_restored`; show the epoch advancing
from 0 to 1.

**Say:** “The primary stops. The sandbox scenario requests independent
SENTINEL authorization, selects the registered backup and advances PHOENIX's
recovery generation. The old generation is fenced, and the backup restores the
validated checkpoint.”

### 1:10–1:30 — Settle once and verify the receipt

**Show:** `payment_settled`, `duplicate_payment_prevented`, and
`recovery_receipt_verified`. Briefly show the receipt and the matching
settlement reference in the exported JSON.

**Say:** “REWIND processes one authorized native-NEAR Sandbox escrow operation.
The repeated operation is rejected and the test asserts the recipient balance
delta. The backend verifies the signed recovery receipt against the emitted
scenario evidence. This is application and Sandbox evidence, not independent
NEAR cryptographic proof verification.”

### 1:30–1:50 — Show warning and quarantine

**Show:** `guardian_warning`, `suspicious_payment_rejected`,
`guardian_quarantined`, and `demo_complete`.

**Say:** “GUARDIAN records the warning and quarantines after an unauthorized
payment attempt. The contract gate rejects it. Quarantine is contract-scoped;
this prototype does not isolate an external host or worker process.”

### 1:50–2:00 — Close with limitations

**Show:** The exported evidence path and report link.

**Say:** “The end-to-end scenario passes in a local Sandbox. The worker is
deterministic, production adapters and key custody are not implemented, and
lost REWIND callbacks keep funds locked. No mainnet or real funds are used.”

## Expected evidence

The harness emits structured events including sandbox configuration, primary
heartbeat, checkpoint, primary failure, backup restoration, settlement,
duplicate prevention, receipt verification, GUARDIAN warning and quarantine,
and completion. The exact sequence and fields can vary with the current test
implementation; use the fresh JSON generated by `npm run demo:local`, not a
hard-coded expected event count. The demo is successful only when the child
process exits successfully, required events are present, the receipt validates
and replay protection accepts it as new. The browser UI is not covered by this
terminal-level assertion.

Keep the narration precise: “Sandbox scenario passed” is supported. “Production
recovery,” “LLM agent,” “independent finalized receipt proof,” or “all funds
recovered” is not supported by this evidence.
